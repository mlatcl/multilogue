## Summary

Treat topic count / subject grain as **Assess EDA with a human in the loop**,
in the spirit of Bishop & Tipping’s hierarchical visualisation (TPAMI 1998):
the analyst sees the **geometry of the fit** (latent / mixture views as models
are fit, merged, and split) **and** reads LLM catalogues of the same bags, then
**locks** a subject list for Address. The two views are complementary — neither
replaces the other. Formats multiverse stops treating a wide \(k\) grid as a
peer dimension that swamps quote / kind / membership.

**Which requirements?** REQ-000A.

## Motivation

Soft MPPCA already profiles topic \(\sigma^2\) and can fit any \(k\), but
**choosing \(k\)** is not the same as profiling noise. On CIMT formats runs, a
default multiverse \(k\)-grid around primary \(k{=}10\) (e.g. \(\{5,7,10,13\}\))
took ~98% of format-gap variance share: \(\ell\) flipped sign across \(k\) while
quote / kind / membership barely moved. That answers “does resolution dominate?”
— useful once, disastrous as the default stability story.

Subject grain is closer to “how many subjects belong in the catalogue?” than to
“which quote threshold?”. Bishop & Tipping (1998) drove hierarchy interactively
from what the human saw in **latent visualisation plots** as mixture / PPCA
models were fit. For civic phrase topics we keep that geometric channel **and**
add a **semantic catalogue** (exemplars + LLM name/description). Merge / split /
keep remains the feedback channel — not automatic maximisation of format-gap
\(\ell\).

Under the multilogue tenet *assess-without-the-question*, browsing and refining
topics without committing to a study metric is **Assess**. Lenses, format gap,
and multiverse under a locked catalogue are **Address**.

## Detailed Description

### Stage boundary

| Stage | Owns |
|---|---|
| **Assess (this CIP)** | Soft-topic EDA: **fit visualisations**, LLM catalogues, machine screen (collapse / tiny mass), merge & split, re-summarise, **lock** subject grain |
| **Address** | Lenses, soft compare, EMD, multiverse with \(k\) held or \(\pm 1\) only |

Do **not** pick primary \(k\) (or merge/split) to maximise format-gap \(\ell\).

### Dual view (both required)

After each fit (and after each merge/split), the analyst sees **both**:

1. **Geometry (Bishop–Tipping channel)** — a latent visualisation of the current
   mixture / local PPCA fit: points in a 2-D view (global or per-node), soft
   responsibilities as colour/opacity or membership cues, component means (and
   where cheap, local subspace / covariance sketch). Hierarchy: parent view of
   the whole set; child views after a split, focused on that component’s mass.
   Re-draw when the model updates so the human watches structure change *as we
   fit*, not only a static end-state scatter.

2. **Semantics (LLM catalogue channel)** — blind harden-view name + description
   over exemplars for each leaf (and for merge candidates / split children).
   Same bags the plot is showing, in words.

Neither view is optional in the Assess loop. Geometry answers “do these look
like separable / nested blobs?”; LLM summaries answer “what are these phrases
about?”. The human decides merge/split/keep using both.

### Interaction model (discrete, small)

Human actions only:

1. **keep** — accept current leaf topics  
2. **merge** \(\{i,j,\ldots\}\) — combine soft mass / MAP bags; re-fit or re-aggregate; **re-plot** and re-summarise the merged subject  
3. **split** \(i\) — fit a local 2- (or few-) component model on that component’s mass; **re-plot** parent vs children and re-summarise  

Optional later: edit LLM title only (naming, not structure). Out of scope for
v1: dragging individual phrases, free-form “make a topic about X”, or
score-driven auto-split criteria as the primary loop.

### LLM role

Blind harden-view labels (existing `make_label_work` / exemplar path) are
**semantic reading aids alongside the plot**, not a replacement for
Bishop–Tipping visualisation and not an automatic selector of \(k\). After
merge/split, re-label only the affected bags to control cost.

### Machine screen (non-decision)

Before or during interaction, surface diagnostics already available from MPPCA
fits (`n_map`, mean max-responsibility, mean entropy, tiny/empty topics,
collapsed?). Use them to **flag** unusable partitions, not to auto-select grain.

### Locked artefact

Persist an explicit lock, e.g. run manifest / checkpoint:

- `primary_k` or leaf topic count  
- topic means / responsibilities (or fingerprint)  
- optional merge/split history  
- `k_multiverse: [k*-1, k*, k*+1]` or `k` omitted from factorial dims  

Address and `run_formats_complexity_demo` consume the lock; default wide
`_default_k_grid` is retired or demoted to an optional one-factor sweep.

### Notebook / pedagogy

Via `scripts/build_notebooks.py` (primary source):

- New Assess section (formats 09 and/or cluster 03): prose on human grain +
  Bishop–Tipping dual view; **fit visualisations** + catalogue cells side by
  side; merge/split demo on synthetic or cached CIMT (plot and labels refresh);
  lock cell (`PRIMARY_K = …`).  
- Address 5e prose: multiverse varies quote / kind / membership (± local \(k\)),
  not a resolution rewrite.

### Library sketch (HOW outline)

Prefer thin helpers over a new UI framework in v1:

- `topic_fit_view(...)` / viz helpers — 2-D latent scatter (or hierarchical
  parent/child panels) from current MPPCA state; update after fit/merge/split  
- `topic_catalogue(phrases, responsibilities, labels_dict, …)` — semantic table  
- `propose_merge(...)` / `propose_split(...)` — return updated soft state + bags
  to re-plot and re-label  
- `lock_subject_grain(...)` — write manifest fields Address already understands  

Full interactive GUI (click-to-split on the canvas) can wait; v1 may be
notebook-driven (call merge/split by id, then show new figure + catalogue).
Faithfulness to Bishop–Tipping is **showing the geometry of the current fit**,
not requiring a desktop app on day one.

Exact module placement (`assess` / `viz` / `mppca` / `cluster`) decided at
implementation; Assess *ownership* of the loop is non-negotiable.

### Alternatives considered

| Approach | Why not primary |
|---|---|
| Wide \(k\) in factorial multiverse | Swamps other dims; wrong stability question |
| Pick \(k\) by max \(\|\ell\|\) | Circular; invents the contrast |
| Pure elbow / BIC / ICL auto-\(k\) | Useful as a screen; still not the human catalogue test |
| Geometry-only (no LLM catalogue) | Incomplete for phrase semantics |
| LLM catalogues only (no fit viz) | Drops the Bishop–Tipping channel; harder to see nest/split structure |
| LLM chooses \(k\) | Relinquishes human authorship of subjects |

## Backward Compatibility

- Existing MPPCA / label / lens / `viz.embedding_scatter` APIs stay; additives
  preferred (hierarchical / responsibility-aware views build on current scatter).  
- Callers that relied on a wide default `k_grid` in formats multiverse must
  pass an explicit grid if they still want a resolution sweep.  
- Cached CIMT runs remain readable; new lock fields optional until Address
  requires them.

## Testing Strategy

- Synthetic planted mixtures: merge then split recovers separable structure;
  catalogue helpers deterministic given seed; viz helpers produce finite 2-D
  coords and honour responsibility colouring.  
- Multiverse default: with locked \(k\), variance shares not dominated by `k`
  on a toy where quote/threshold is planted dominant (extend 05-style toy).  
- Notebook smoke / FakeClient path green without interactive input (scripted
  lock or default keep; figures still render).
