## Summary

After CIP-0005, multilogue owns constrained σ²\* selection (`select_sigma2_in_band` / `select_sigma2_constrained`) but **not** the stability-curve neighbour rules both consumers use for soft-membership sensitivity: one step harder / softer, hard (min σ²), and a named rule registry. Promote those helpers into `multilogue.soft` so formats `rule_sigma2` and pub `SIGMA2_RULES` stop drifting.

**Which requirements does this CIP address?** REQ-0008 (extends soft-membership methodology).

## Motivation

Gap analysis (2026-10-16) found the same neighbour logic in:

- `dialogue_formats.soft_lenses.rule_sigma2`
- `pub_dialogue.multiverse.select_sigma2_one_step_harder|softer|hard` + `SIGMA2_RULES`

Constrained selection is already shared; the sensitivity rules are the next duplicated slice of soft methodology. Without promotion, multiverse and soft-lens notebooks will re-copy grid-neighbour math whenever the band rule evolves.

## Detailed Description

### API (target)

In `multilogue.soft` (or a thin submodule re-exported from `soft`):

- `select_sigma2_one_step_harder(curve, n_lenses) -> float`
- `select_sigma2_one_step_softer(curve, n_lenses) -> float`
- `select_sigma2_hard(curve, n_lenses=…) -> float` — min σ² on the swept grid
- `SIGMA2_RULES: dict[str, Callable]` — at least `constrained`, `one_step_harder`, `one_step_softer`, `hard`
- Optional: accept a `rule` string + curve + n_lenses convenience (`apply_sigma2_rule`)

Behaviour must match pub-dialogue’s current definitions (grid neighbour of **constrained** σ²\*, clipped to the grid). Formats’ `rule_sigma2(curve, star, rule)` can become a thin adapter that maps display labels (`"one step harder"`, `"σ²* (stability)"`, …) onto the registry.

Legacy pub rules (`min_emd`, `median`) stay **out** of multilogue (or behind an explicitly named `LEGACY_SIGMA2_RULES` if needed for reproduction only — prefer keeping legacy in pub).

### Out of scope

- Soft-weighted group compare (CIP-0007)
- Study ℓ / multiverse dimensions
- Changing the canonical support band

## Implementation Plan

1. Port neighbour helpers + tests from pub `test_multiverse_sigma2` patterns into `tests/test_soft.py`.
2. Re-export from `multilogue.soft`; document in concepts/weighting or soft API docs.
3. Consumer backlog (after Accept): thin pub `multiverse` and formats `rule_sigma2`.

## Backward Compatibility

Additive for multilogue. Consumers switch via thin re-exports; display-string mapping stays local in formats if needed.

## Testing Strategy

Synthetic stability curves (as in existing soft / multiverse_sigma2 tests): constrained index known; harder/softer are adjacent grid points; hard is grid minimum; empty-band fallback still uses unconstrained min-EMD for `constrained` only.
