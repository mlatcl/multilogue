## Summary

`multilogue.weight.group_compare` supports **hard** categorical columns only. Both consumers already implement soft mixture weights × document/group share contrasts (formats `soft_compare` / `_doc_profiles`; pub soft-weighted AI–nonAI pp). Promote a **generic** soft-weighted profile + bootstrap group contrast into multilogue so Address notebooks can call one API without copying bootstrap loops.

**Which requirements?** REQ-0004 (weighting), REQ-0008 (soft memberships as Address input).

## Motivation

CIP-0005 made soft mixture weights a shared primitive. The next step in both papers is *using* those weights in document-weighted comparisons. Leaving that loop in each consumer duplicates RNG/bootstrap conventions and invites silent divergence (formats format-pair vs pub AI/nonAI maps).

## Detailed Description

### Proposed API (sketch)

In `multilogue.weight` (or `multilogue.soft` re-exporting weight helpers):

1. **`soft_doc_profiles(phrases, W, *, doc_col, cluster_col) -> DataFrame`**  
   Per document: mean of mixture rows for that document's cluster assignments (formats `_doc_profiles`).

2. **`soft_group_compare(phrases, W, lens_names, group_col, rng, *, groups=None, doc_col=…, cluster_col=…, reps=…, min_gap=…) -> DataFrame`**  
   Document-weighted soft lens shares per group with cluster-bootstrap intervals; when two groups, difference columns (generalising formats `soft_compare` and the continuous share part of pub soft R2).

Study-specific naming (`chatbot`/`workshop`, `difference_w_minus_c`, AI salience ranking) stays in consumers as thin renames.

### Out of scope

- Paper ℓ definitions
- Choosing σ²\* (CIP-0005 / CIP-0006)
- Hard `group_compare` behaviour changes
